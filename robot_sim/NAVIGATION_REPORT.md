## Сделано

- Физическая модель Burger-style: масса 1.62 кг, рассчитанная инерция, исправленные оси колёс, контакты,
  устойчивый центр масс, трение и ограничения ускорения. Это суррогат, не калибровка по реальному TurtleBot3.
- Камера 320×240 / 5 Гц, lidar с шумом 3 мм, контактный сенсор, ground truth для независимой проверки.
- ROS 2 Jazzy / Gazebo Harmonic; map_server, AMCL, NavFn A*, DWB, BT Navigator, replanning, costmaps.
- TF: map → odom → base_footprint → base_link → laser / camera_link → camera_optical.
- Защитный gateway: пределы скорости, остановка при потере команд/сенсоров, препятствии и контакте корпуса.
- Три сцены warehouse / apartment / courtyard: разные препятствия и PBR albedo/normal/roughness 512×512.
  Миры и occupancy maps генерируются из одного layout; внешние текстуры не нужны.
- RGB-кадр → Qwen3.5-0.8B AsyncLLM → выбор непосещённого маркера → NavigateToPose.
  Координаты маркеров известны карте; модель не управляет моторами напрямую. Сохраняются решения и SHA256 кадров.

## Границы результата

- Визуальный порядок 0.8B: green → red → blue. Успешный путь 21.04 м почти вдвое длиннее заданного порядка Nav2.
  Это подтверждает работу контура, но не точное распознавание/оптимальное планирование. Нужны image ablation и серия сценариев.
- Vision выбирает цель из известных координат. Неизвестные объекты по одному RGB-кадру в 3D не локализуются.
  Навигация/объезд — Nav2 по lidar и карте. 9B не загружалась.
- Сцены процедурные, не фотореалистичные; препятствия статические.
- DiffDrive идеализирован с пределами ускорения. Joint effort limits не заменяют PID и модель тока двигателя.
  Нет реальной калибровки сцепления/торможения, SLAM и аппаратных испытаний.
- Ранний неуспешный Nav2-прогон выявил завал корпуса: COM был около оси колёс.
  Смещение COM внутрь треугольника опор устранило наклон и ошибку одометрии; неуспешные логи сохранены.
