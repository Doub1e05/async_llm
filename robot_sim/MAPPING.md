# Построение карты по датчикам мини-ровера

## Что реализовано

Проверяемый традиционный стек ROS 2 Jazzy:
1. Колёсные энкодеры и IMU → EKF robot_localization.
2. 2D lidar + odom/TF → SLAM Toolbox, построение /map с нуля.
3. Lidar + оценка позы → байесовская локальная occupancy grid с временным сроком наблюдений.
4. RGB + CameraInfo + timestamped extrinsics → цвет измеренных лидаром поверхностей.
5. Occupancy grid → отдельный слой риска с запасом расстояния.

Карта сверху вычисляется из измерений. /overview/image_raw, готовые maps/*.pgm,
позы моделей и геометрия мира не являются входами алгоритма.
Истинная поза поступает только в отдельный mapping_evaluator.
Нет LLM, AMCL, заранее загруженной карты или скрытого выбора траектории по ground truth.

## Системы координат и недублирующаяся оценка

map → odom публикует SLAM Toolbox.
odom → base_footprint публикует только EKF.
base_footprint → base_link → laser/camera_optical/imu_link берутся из URDF.
RoverDrive запускается без собственной odom TF; идеальная одометрия /wheel/ideal
не участвует в оценивании.

EKF объединяет линейную скорость, мягкое неголономное ограничение vy≈0 и угловую
скорость энкодеров с гироскопом. Не объединяются одновременно коррелированные
положение/ориентация и скорости одной колёсной одометрии.
Истинный yaw из Gazebo IMU удаляется: orientation_covariance[0]=-1.
Ускорение IMU доступно, но в этом плоском сценарии не интегрируется в положение:
для маленького робота дрейф смещений и влияние гравитации дают большой риск ошибки.

## Реалистичность датчиков

Все параметры — явно выбранные допущения для прототипа, а не измеренные
характеристики конкретного физического ровера.
Полный профиль: robot_sim/config/mapping_sensors.yaml.

- Lidar: 360 лучей, 10 Гц, рабочий диапазон 0.12–6 м.
  Дополнительный шум σ=10 мм + 0.2% дальности, постоянное смещение 5 мм,
  дискретизация 5 мм, ошибка угла установки 0.2°, пропуски 2% лучей,
  0.3% выбросов, 1% потерянных сообщений.
  Задержка 45±10 мс; одиночные грубые выбросы отбрасываются.
- IMU: 50 Гц; шум гироскопа 0.006 рад/с, начальный bias 0.003 рад/с,
  медленное случайное изменение bias; шум ускорения 0.08 м/с².
  Задержка 15±5 мс. Абсолютный компас не симулируется.
- Энкодеры: 2048 отсчётов/оборот, ошибки эффективных радиусов +1% / −0.8%,
  ошибка колеи +1%; публикация около 50 Гц, задержка 25±5 мс.
  Фактическое проскальзывание возникает в физическом движке.
- RGB: 320×240, 5 Гц, шум пикселей, JPEG quality 85, потеря 2% кадров,
  задержка 70±10 мс, небольшая ошибка фокусного параметра калибровки.

Задержки заданы в simulation seconds, временные метки измерения сохраняются.
EKF обрабатывает запаздывающие измерения с историей 1 с.
Для RGB ассоциации используется буфер и допустимое расхождение времени ≤120 мс;
межкадровое движение компенсируется через odom TF.
Случайный seed фиксируется; из-за асинхронного порядка callbacks битовая идентичность
разных прогонов не гарантируется. ROS bag сохраняет конкретные наблюдения.

## Общая и динамическая карты

/map — глобальная 2D SLAM occupancy grid, разрешение 4 см, loop closure включён.
Неизвестное пространство не объявляется свободным. Движущиеся объекты могут
оставлять следы в долговременной SLAM-карте; для текущих препятствий используется
отдельная локальная карта.

/mapping/dynamic_grid — сетка в odom, 4 см/клетку.
Обновление log-odds: +0.85 за препятствие, −0.40 за наблюдаемое свободное место.
За один scan клетка обновляется не более одного раза; уверенность ограничена.
Свободными становятся только клетки до измеренной поверхности. За препятствием
ничего не очищается. Inf обрабатывается как отсутствие препятствия до max range,
NaN/потерянный луч не очищает пространство.

После 4 с без наблюдения клетка становится неизвестной, а не свободной.
Поэтому исчезнувшее препятствие либо очищается новым лучом, либо теряет
актуальность при отсутствии наблюдений.

/mapping/costmap — отдельный консервативный слой риска: препятствия расширены
на 20 см вокруг измеренных занятых клеток. Это запас для габарита, ошибок
локальной оценки и остановки; он не выдаётся за физический размер препятствия.

RGB-слой привязывается к фактически измеренным точкам лидара по матрице камеры
и TF. Это цвет поверхности, а не распознавание класса объекта. Дальность из
одного RGB-кадра не выдумывается. Проекция не меняет геометрию occupancy grid.
Точки окрашиваются только в поле зрения камеры и при корректной синхронизации.
Экранная голубая окружность показывает ковариацию одометрии с ограничением
радиуса отрисовки; это не гарантия абсолютной точности.
Малиновые стрелки — кандидаты движения кластеров лидара; возможны ложные
срабатывания и смена ID. Они не используются для очистки карты или безопасности.

## Запуск

На сервере, строго из /home/motovilovil/async_llm/async_llm:

```bash
bash robot_sim/scripts/run_mapping.sh --duration 150 --record-bag
```

По умолчанию используется отдельный ROS_DOMAIN_ID=83.
Для другого домена: ROBOT_MAPPING_DOMAIN_ID=84 bash ... .
Все процессы наследуют ограничение на один логический CPU и Mesa llvmpipe:
GPU не используется. На одном CPU симуляция может идти медленнее реального времени.

Результаты:
- live.png и map_frames/ — вид сверху, построенный по датчикам;
- global_map.pgm + global_map.yaml — карта SLAM для ROS/Nav2;
- local_map.npz — актуальная динамическая сетка, last_seen и метаданные;
- sensors_bag/ — запись noisy sensors, /odom и TF;
- sensor_profile.yaml, ekf.yaml, slam.yaml, source_hashes.json — условия прогона;
- summary.json — независимые измерения качества;
- topic_audit.json, resource_audit.json — проверка входов и ресурсов, если выполнен аудит.

Записанный /odom и /tf — результаты исходного оценивания.
При повторном запуске EKF из ROS bag не воспроизводите их одновременно
с новым EKF: проигрывайте только /scan, /imu/data, /wheel/odometry,
camera topics, и задавайте статические TF из сохранённой калибровки.
Используйте --clock; запись выполнена с --use-sim-time.

## Проверка

Скриптовой траекторией робот делает обход четырёх точек. Отдельный тестовый ящик
перемещается поперёк обзора. Контроллер маршрута пользуется /odom и фронтальным
сектором lidar; ground truth используется только для метрик.
Само по себе завершение такого маршрута не является оценкой Nav2 или LLM.

Проверки включают:
- построение карты без заранее заданной occupancy grid;
- обнаружение и очистку старого места движущегося препятствия;
- ошибку wheel-only и wheel+IMU одометрии;
- ошибку SLAM-позы в общем начальном кадре без подгонки по истине;
- расстояния занятых клеток до истинных статических поверхностей (только оценщик);
- изображение, временную синхронизацию и использование камеры;
- отсутствие GT-подписки у EKF, SLAM и mapper;
- ограничение каждого потока одним CPU, отсутствие GPU fd.

```bash
source robot_sim/scripts/robot_env.sh
python -m unittest discover -s robot_sim/tests -v
```

## Что пока не моделируется и не доказано

Это 2D indoor-прототип. Один горизонтальный lidar не видит все низкие пороги,
нависающие детали, стекло, зеркала и другие сложные поверхности.
RGB-аннотация не заменяет стерео/RGB-D или 3D lidar и не подтверждает проходимость.
Не смоделированы реальный rolling shutter, полный покадровый sweep/deskew лидара,
погода, освещение улицы, реальная оптика и отражательная способность материалов.
Газебо выдаёт мгновенный lidar snapshot; scan_time задан как частота получения,
time_increment=0, чтобы не притворяться, что лучи сняты последовательно.
При текущей малой скорости это допустимое упрощение, которое надо отдельно
проверить при переносе на физический сенсор.

Физика шасси и контактные параметры остались приближёнными из ROVER.md.
Реальные шумы, задержки, extrinsics, выравнивание времени и ковариации необходимо
измерить на оборудовании. Успешная симуляция не доказывает качество езды в реальности.

Итоговая оценка SLAM выполняется офлайн по записанным TF на временных метках
оценочных измерений. Это позволяет сопоставить весь маршрут, а не только немногочисленные
успешные онлайн-запросы TF. Пространственная подгонка по ground truth не выполняется.
Неизвестные клетки экспортируются серым значением 128; оно остаётся неизвестным
при free_thresh=.35 и occupied_thresh=.65.
